RigorousInvariantMeasures.MonotonicBranch — Type

Type used to represent a "branch" of a dynamic. The branch is represented by a map f with domain X=(a,b). X[1] and X[2] are interval enclosures of a,b.

The map must be monotonic on [a,b]. Note that this is not the same thing as being monotonic on hull(X[1], X[2]): for instance, take the map x → (x-√2)^2 on [√2, 1]: the left endpoint X[1] will be prevfloat(√2)..nextfloat(√2), but then the map is not monotonic on the whole hull(X[1], X[2]) because it also contains points that lie left of √2. This is a tricky case that must be dealt with.

Enclosures Y[1], Y[2] for f(a), f(b) and increasing may be provided (for instance if we know that Y=(0,1)), otherwise they are computed automatically.

RigorousInvariantMeasures.PwMap — Type
PwMap(Ts, endpoints, y_endpoints_in = nothing; full_branch = false, T)

Build a piecewise map from the branch functions Ts and the endpoints separating them.

T is the interval precision the branches are built at. It defaults to the precision of endpoints, so passing Interval{BigFloat} endpoints gives a BigFloat dynamic and everything downstream — notably preimages and hence the assemblers — runs at that precision.

Note that T does not reach inside the branch functions: a coefficient written as a Float64 literal in Ts stays a Float64, and rounds as one. Write the coefficients at the target precision if that matters.

RigorousInvariantMeasures.PwMap — Type

Dynamic based on a piecewise monotonic map.

The map is defined as T(x) = Ts[k](x) if $x \in [endpoints[k], endpoints[k+1])$.

y_endpoints ($k \times 2$ matrix) contains the result of applying Ts to the endpoints of each interval. These can be filled in automatically from endpoints, but sometimes they are known to higher accuracy, for instance for x -> mod(3x, 1) we know that it is full-branch exactly. It is assumed that the map will send its domain hull(endpoints[begin],endpoints[end]) into itself.

the array branches is guaranteed to satisfy branches[i].X[end]==branches[i+1].X[begin]

RigorousInvariantMeasures.dfly_inf_der — Function

dfly inequality for maps with infinite derivatives.

The strategy to compute it follows a variant of Lemma 9.1 in the GMNP paper:

  • we find a "problematic set" I by taking a small interval of size radius(branch domain)/2^3 around each endpoint with infinite derivative;
  • we find l such that T >= l for each point in I
  • we compute the dfly coefficients as in the lemma.
  • we repeat the computation replacing 2^3 with 2^4, 2^5, ... 2^15 and take the best estimate among these.

RigorousInvariantMeasures.has_monotone_mod1_lift — Method
has_monotone_mod1_lift(D::PwMap)

Whether D, read as a map of the circle $[0,1]/\{0\sim1\}$, is the reduction mod $1$ of a strictly monotone $\tilde T:[0,1]\to\mathbb R$. Two conditions: all branches run the same way, and at every interior branch point $a_i$ the two one-sided limits are the two ends of the unit interval, $T(a_i^-)=1$ and $T(a_i^+)=0$ for increasing branches and the other way round for decreasing ones. Then $\tilde T = T + n_i$ on the $i$-th branch, with $n_i$ the number of interior branch points to the left of $I_i$, is continuous and monotone on the whole of $[0,1]$; conversely a monotone lift forces those limits, since an interior branch point is a point where the lift crosses an integer. Everything built by mod1_dynamic has this form, with the first and the last branch free to be partial.

The condition is read off the stored image enclosures br.Y and asks for exact equality with the thin intervals $0$ and $1$: a branch whose image endpoint is known only up to an enclosure around $1$ does not qualify, and false is then the answer that keeps the caller on a statement needing no hypothesis. It is the hypothesis of one of the two statements dfly(VarCircle, L1, D) computes, the lift being what makes the jumps of the inverse branches at the interior branch points pair with the jumps of $f$ there instead of being paid for separately. It does not establish that the lift is $C^1$ across the branch points, which is a separate property of how the branches were built and is what would make the $\theta$ of that statement zero.

RigorousInvariantMeasures.BZ — Method
BZ()

The three-branch model of the Belousov-Zhabotinsky reaction, as the PwMap with branches

T(x) = (A - (1/8 - x)^(1/3)) e^(-x) + B,            0 ≤ x ≤ 1/8,
T(x) = (A + (x - 1/8)^(1/3)) e^(-x) + B,          1/8 ≤ x ≤ 3/10,
T(x) = C (10 x e^(-10x/3))^19 + B,               3/10 ≤ x ≤ 1,

on the partition 0 < 1/8 < 3/10 < 1. The three constants are enclosed from the decimal expansions written in the source, A and C as thin BigFloat intervals rounded to Float64 and B as the interval between the two expansions given for it, and the branch endpoints are the images of the partition points under the branch they belong to, so that the map is built from enclosures throughout.

The cube root is written with the rational exponent 1//3: the Newton step for the preimages takes the derivative through Taylor1{Interval} ^ Interval, where TaylorSeries truncates the exponent to an integer and throws.

RigorousInvariantMeasures.fastpow — Method
fastpow(x, α)

The power x^α evaluated as exp(α log x), which on an interval argument is cheaper than the interval power and returns a decorated interval rather than the _NG of ^; the branch at x = 0 is there because log of the thin zero is -∞ and exp(α · -∞) comes back as the empty interval, so the identity at zero has to be supplied.
